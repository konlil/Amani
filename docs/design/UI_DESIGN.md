# LLM3dEngine 用户交互界面设计

## 概述

LLM3dEngine 的用户交互界面，用户在此与 LLM 对话协作开发游戏，同时实时预览 LLM 生成的游戏产品。

## 技术选型

- 桌面应用框架：Tauri（Rust 后端，体积小）
- 前端：React + TypeScript
- 引擎集成：Godot 引擎作为子进程运行，预览区使用 overlay 模式对齐引擎窗口
- LLM 接入：OpenAI 兼容接口（后续可扩展多模型）
- 通信：Tauri 后端与引擎之间通过本地 IPC 长连接

## 整体架构

```
┌──────────────────────────────────────────────────┐
│                Tauri 桌面应用                      │
│  ┌──────────────┐  ┌──────────────────────────┐  │
│  │  对话面板     │  │  预览窗口                 │  │
│  │  (React)     │  │  开发模式 / Play 模式     │  │
│  └──────┬───────┘  └───────────┬──────────────┘  │
│  ┌──────┴──────────────────────┴──────────────┐  │
│  │           Tauri 后端 (Rust)                 │  │
│  │  • OpenAI 兼容 API 调用                     │  │
│  │  • 引擎子进程管理（启动/停止/重启）           │  │
│  │  • 项目文件读写                              │  │
│  │  • 本地 IPC 连接引擎协调层                   │  │
│  └──────────────────┬─────────────────────────┘  │
└─────────────────────┼────────────────────────────┘
                      │ Local IPC
         ┌────────────┴─────────────┐
         │   Godot 引擎进程          │
         │   协调层 ← → QuickJS     │
         │   渲染窗口独立/overlay    │
         └──────────────────────────┘
```

### 三层职责

- React 前端：对话 UI、模式切换、布局管理
- Tauri Rust 后端：LLM API 调用、引擎进程管理、文件操作
- Godot 引擎进程：编译执行 TS、渲染游戏、状态收集

## 界面布局与模式

### 两个维度的模式

**信息密度维度：**
- 普通模式：对话流里只显示 LLM 的自然语言回复和进度，隐藏代码/日志/错误等技术细节
- 高级模式：对话流里内联展示代码块、编译日志、错误信息，均可折叠/展开

**运行状态维度：**
- 开发模式：LLM 和用户协作开发游戏，预览窗口为自由相机视角
- Play 模式：用户以玩家身份体验和测试游戏

### 模式组合

| | 普通模式 | 高级模式 |
|---|---|---|
| 开发模式 | 对话 + 预览，只显示自然语言回复和进度 | 对话 + 预览，内联展示代码/日志/错误（可折叠） |
| Play 模式 | 分栏或全屏可选，用户玩游戏，可给反馈 | 同上，额外显示运行时性能指标、控制台日志 |

### 布局规则

- 开发模式：左右分栏，左 40% 对话，右 60% 预览，分栏可拖拽调整
- Play 模式：用户可选分栏或全屏
  - 分栏：左边对话面板仍可用，用户边玩边反馈
  - 全屏：预览占满窗口，ESC 退出回到开发模式
- 普通/高级模式通过顶部开关切换，切换时对话内容不丢失，只是技术细节块的显示/隐藏
- 顶部工具栏：模式切换（普通/高级）、开发/Play 切换、项目设置

## 对话面板设计

### 消息流

- 用户消息靠右，LLM 消息靠左
- 支持 Markdown 渲染

### 输入框

- 底部固定
- 支持多行输入，Shift+Enter 换行，Enter 发送

### 检查点交互

LLM 到达检查点时，对话流里弹出检查点卡片：
- 包含 LLM 的问题
- 预览截图缩略图
- 用户直接在卡片里回复

### 高级模式内联块

- 代码块：语法高亮，显示文件名，可折叠
- 编译结果：成功显示绿色勾，失败显示红色错误列表
- 运行状态：JSON 格式化展示，可折叠
- 截屏：缩略图内联，点击放大

### 普通模式

以上技术块全部隐藏，只保留 LLM 的自然语言描述和检查点卡片。

## 预览窗口设计

### 预览接入方式

- Godot 引擎作为子进程启动，渲染到独立窗口
- Tauri 在预览区测量目标矩形，驱动 Godot 无边框窗口以 overlay 方式贴合该区域
- macOS 当前不做 NSView 真嵌入，而是通过窗口坐标同步实现视觉上的内嵌预览
- 引擎和 Tauri 之间通过本地 IPC 长连接通信（状态同步、命令下发）

### 开发模式

- 自由相机：鼠标右键拖拽旋转视角，滚轮缩放，WASD 移动
- 顶部叠加半透明状态栏：FPS、当前场景名、实体数量
- 底部叠加 Play 按钮，点击进入 Play 模式
- LLM 每次修改代码后，引擎重启场景，预览自动刷新

### Play 模式

- 引擎以游戏运行时模式启动，玩家视角，键鼠输入直接传给游戏
- 分栏布局时左边对话面板仍可用
- 全屏布局时预览占满窗口，ESC 退出回到开发模式
- 顶部叠加退出按钮/提示

## 数据流

### 完整交互循环

```
用户输入 "加一个会巡逻的敌人"
    ↓
Tauri 后端 → OpenAI 兼容 API（携带引擎 .d.ts 作为上下文）
    ↓
LLM 返回 TS 代码（流式输出，对话面板实时显示）
    ↓
Tauri 后端将 TS 文件写入项目目录
    ↓
Tauri 通过本地 IPC 通知引擎："新代码，请编译执行"
    ↓
引擎协调层：tsc 编译 → ESLint 检查
    ↓ 失败 → 错误 JSON 返回 → Tauri 转发给 LLM 自动修复 → 重试
    ↓ 成功
QuickJS 执行 → 场景更新 → 预览窗口刷新
    ↓
引擎返回：场景状态 JSON + 截屏
    ↓
Tauri 后端将反馈发给 LLM，LLM 判断是否需要继续迭代
    ↓
到达检查点 → 对话面板弹出检查点卡片 → 等用户反馈
```

### 关键设计点

- LLM 编译失败时自动重试，不打扰用户（普通模式下用户只看到"正在调整..."）
- 高级模式下每一步都在对话流里可见
- LLM 的流式输出实时渲染到对话面板

## 目标用户

通过普通/高级模式切换兼顾不同用户：

- 普通玩家/非技术用户：普通模式，用自然语言描述需求，看到结果
- 游戏设计师：普通模式为主，偶尔切高级模式查看细节
- 开发者：高级模式，查看代码、编译过程、调试信息
